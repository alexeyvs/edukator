# Edukator

Домашнее приложение для подготовки к вступительным тестам в 7 класс по
русскому, английскому и математике. Бюджет подготовки — около 40 часов, поэтому
приложение не «проходит программу», а ищет пробелы и тратит время ученика
только на них.

Проектная спека: [`docs/superpowers/specs/2026-08-07-edukator-design.md`](docs/superpowers/specs/2026-08-07-edukator-design.md).
План первого этапа: [`docs/plans/20260807-edukator-core.md`](docs/plans/20260807-edukator-core.md).

## Что уже есть

Готов **этап 1 — ядро и данные**: всё, что работает без LLM и без интерфейса.

| Модуль | Назначение |
|---|---|
| `server/db.ts` | SQLite (`better-sqlite3`), схема семи таблиц, идемпотентные миграции, профиль |
| `server/curriculum.ts` | загрузка карты тем из `content/curriculum/*.json`, валидация по JSON Schema, граф тем, синхронизация с `topic_state` |
| `server/normalize.ts` | сверка ответа ученика с эталоном по `answer_format` (`number` / `text` / `choice`) |
| `server/mastery.ts` | модель знаний: `mastery`, `confidence`, пробелы, интервальное повторение |
| `server/scheduler.ts` | приоритет тем и план забегов на день |
| `server/forecast.ts` | прогноз оценки, полоса погрешности, снимки и тренд |
| `scripts/extract-toc.ts` | оглавление учебника из PDF → `content/raw-toc/<subject>.txt` |
| `scripts/build-curriculum.ts` | оглавление → карта тем через codex → `content/curriculum/<subject>.json` |

Впереди: генерация заданий через codex (этап 2), экран забега и триаж (этап 3),
дашборд, боссы и диктант (этап 4).

## Установка

Нужен Node 26 или новее.

```sh
npm install
```

npm 11 блокирует install-скрипты зависимостей. Разрешения для `better-sqlite3`
(нативная сборка) и `esbuild` (бинарник) уже зафиксированы в `allowScripts` в
`package.json` — без них не поднимется ни база, ни vitest. Если npm всё же
спросит, ответ даёт `npm approve-scripts`.

## Запуск

```sh
npm run dev     # tsx watch, перезапуск по изменению
npm start       # разовый запуск
```

Сервер слушает `0.0.0.0:3000` (порт переопределяется `PORT`) — чтобы заходить с
телефона и планшета из домашней сети. Авторизации нет: приложение не выходит за
пределы дома.

Проверка живости:

```sh
curl http://localhost:3000/api/health
# {"status":"ok","version":"0.1.0","database":"ok"}
```

Файл базы — `edukator.db` в корне репозитория, путь переопределяется
`EDUKATOR_DB` (тесты пользуются этим и работают на временных файлах). Схема
домигровывается при каждом открытии базы, отдельной команды миграции нет.

## Проверки

```sh
npm test        # vitest, 241 тест
npm run coverage
npm run typecheck
npm run lint
```

`coverage` держит порог 80% (строки, ветви, функции) на четырёх модулях ядра —
`normalize`, `mastery`, `scheduler`, `forecast`. Порог висит именно на них:
они детерминированы, а дефект в них тихо портит учебный план, не роняя ни
одного теста. Скрипты извлечения PDF и сборки карты завязаны на сканы и на
codex, общий порог по репозиторию был бы враньём.

## Сборка карты тем

Карты трёх предметов уже лежат в `content/curriculum/` и в репозитории. Заново
собирать их нужно, только если меняются учебники или состав тем.

Конвейер из двух шагов.

**1. Оглавление учебника из PDF**

```sh
npm run extract-toc -- --subject math --pdf ~/Downloads/merzljak-6.pdf
```

Флаги: `--pages 333-334` — явный диапазон вместо поиска по эвристике;
`--scan 15` — сколько страниц смотреть с каждого края книги; `--no-ocr` —
запретить откат в распознавание; `--out` — другой каталог для результата.
Результат пишется в `content/raw-toc/<subject>.txt`.

**2. Карта тем через codex**

```sh
npm run build-curriculum -- --subject math
```

Флаги: `--toc` — другой файл оглавления, `--out` — другой каталог,
`--attempts 3` — сколько раз перезапрашивать модель, `--model` — другая модель.
Скрипт требует 20-25 тем на предмет, прогоняет ответ через тот же валидатор,
что и файл из репозитория (схема, дубли `id`, ссылки в `prereqs`, циклы, число
тем в пределах 15-30), и при провале уходит на следующую попытку, дописав текст
ошибки в промпт. После трёх неудач падает с отчётом по всем попыткам.

## Подводные камни

Здесь собрано то, что стоило времени при реализации и не выводится из кода.

**codex висит вечно без `< /dev/null`.** Вызов обязан закрывать stdin, иначе
процесс ждёт ввода бесконечно и никакой таймаут об этом не сообщает. В коде это
выражено как `stdio[0] = 'ignore'` в `spawn`; есть тест с исполняемой
заглушкой, читающей stdin через `cat`, — он повиснет по таймауту, если строку
когда-нибудь потеряют. Полная форма вызова:

```sh
codex exec --ephemeral --skip-git-repo-check -m gpt-5.6-terra \
  --output-schema <schema> --output-last-message <out> "<промпт>" < /dev/null
```

**`--output-schema` не принимает половину JSON Schema.** Запрос падает с
`invalid_json_schema` ещё до обращения к модели на `uniqueItems`, `minItems`,
`pattern`, `minLength`, `minimum`/`maximum` и родственных ключевых словах.
Поэтому в рабочий каталог кладётся очищенная копия `schemas/curriculum.json`, а
ограничения не теряются: их проверяет валидатор, диапазоны продублированы
словами в `description` и в промпте. Единственный источник правды —
`schemas/curriculum.json`, рукописной копии схемы в коде нет.

**Корень схемы — объект, а не массив.** Структурированный вывод допускает в
корне только объект, поэтому карта имеет вид `{ subject, topics[] }`.

**Все три учебника — сканы без текстового слоя.** `pdf-parse` вытаскивает из
818 страниц ноль символов, так что добавлен откат в OCR:
`scripts/ocr-pdf.swift` рендерит страницу через PDFKit и распознаёт системным
Vision (`ru-RU` + `en-US`). Vision выбран потому, что он уже есть в macOS,
знает русский и не требует ни установки, ни языковых моделей; плата — эта ветка
работает только на macOS. `pdf-parse` остался первой попыткой: для PDF с
текстовым слоем OCR не запускается.

**OCR читает оглавление по колонкам.** Сначала идут все названия, потом
отдельным блоком все номера страниц, а «§» часто распознаётся как «$».
Эвристика «название … номер страницы» на таком тексте не работает, поэтому
пункт опознаётся тремя способами: отточие с номером в конце строки, маркер
раздела в начале строки и голый номер страницы. Голые номера засчитываются
только там, где уже есть хотя бы три названия, — иначе страница «Ответы к
упражнениям» выглядит идеальным оглавлением.

**Оглавление бывает в конце книги** (математика — с. 333, русский — с. 314-318,
английский — с. 3), а OCR страницы стоит около секунды. Поэтому просматриваются
не все страницы, а по 15 с каждого края.

**`\b` в JS работает только с ASCII.** `/^глава\b/` не находит границу после
кириллицы и не срабатывает никогда. Граница слова выражена через `(?!\p{L})`.

**Внешние ключи SQLite включаются на каждом соединении.** `PRAGMA
foreign_keys = ON` живёт в `openDatabase`, а не в схеме; открытие базы мимо
`openDatabase` молча отключает всю ссылочную целостность.

**Ajv кладёт виновника ошибки в `params`, а не в `message`.** Текст ошибки
собирается из обоих — иначе «must NOT have additional properties» не говорит,
какое поле лишнее.

## Решения ядра

**Юникодный минус.** `−45` и `-45` — одно и то же число; туда же запятая как
десятичный разделитель, дробь `a/b` (тема `math.common-fractions` объявлена
как `number`, иначе «3/4» не сошлось бы с «0,75») и пробел между разрядами
(«45 000» — одно число, но «12 3» — два). Причина отказа возвращается отдельным
полем (`mismatch`, `empty`, `no-number`, `ambiguous-number`): разбору спора
через LLM на этапе 3 нужно различать «не то число» и «в ответе их два».
Неоднозначный эталон в задании — дефект банка, а не ошибка ученика: проверка
падает с внятной ошибкой и делается до проверки ответа.

**Уверенность затухает непрерывно.** Хранимая `confidence` свежа только на
момент `last_seen`, текущее значение считает `confidenceAt(state, now)`.
Побочный эффект: после долгого простоя тема выпадает из «пробелов» — данных о
ней фактически больше нет.

**Подсказка ослабляет только рост.** Неверный ответ с подсказкой падает на
общих основаниях: подсказали, и всё равно мимо — это худший сигнал, а не
смягчающий.

**Предметы не чередуются строго.** Строгое чередование по максимуму отставания
выбрасывает третий предмет из плана совсем. Спрос предмета считается как
`SUBJECT_FLOOR + deficit` и делится на число уже назначенных ему забегов: при
отставании 1.0 / 0.5 / 0.2 план из шести забегов даёт 3 / 2 / 1 без двух
забегов подряд по одному предмету.

**«Считать не из чего» — это `null`, а не двойка.** Карта без тем с
`exam_weight ≥ 1` означает «неизвестно»; оценка 2.0 была бы утверждением о
ребёнке, которого никто не проверял.

## Что делает человек

Автоматические тесты проверяют структуру карты тем, но не её содержание. Перед
этапом 2 нужно прочитать `content/curriculum/*.json` и убедиться, что темы
соответствуют программе 6 класса, а `prompt_seed` даёт осмысленные задания.
Туда же — правка `exam_weight` по известным слабым местам конкретного ребёнка
и точная дата экзамена в профиле: от неё считается рост срочности тем.
