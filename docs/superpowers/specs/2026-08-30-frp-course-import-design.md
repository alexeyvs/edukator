# Массовый импорт курсов из федеральных рабочих программ

## Контекст

В каталоге едукатора три курса — `math`, `russian` и `english`, все за 7 класс,
заведённые legacy-bootstrap из `content/curriculum/*.json`. Конвейер настраиваемых
курсов (`docs/superpowers/specs/2026-08-22-configurable-courses-design.md`) умеет
всё нужное, чтобы курсов стало шестьдесят, но заводить их пока нечем: оператор
загружает PDF по одному через админку и ждёт каждый черновик руками.

Требование к содержанию сформулировано коротко: темы курса обязаны соответствовать
официальной образовательной программе. Отсюда выбор источника. Сканы учебников
отвергнуты: это чужие произведения, а их загрузка в `catalog/` сделала бы копию
постоянной частью данных прода и резервных копий. Взамен берутся **федеральные
рабочие программы** (ФРП) с edsoo.ru — официальные документы, в которых уже лежит
поурочно-тематическое планирование по классам. Программа вдобавок точнее учебника:
она одна, а учебников по ней несколько.

Учебник конвейеру и не нужен. `buildCourseDraft` извлекает из источника карту тем —
`title`, `exam_weight`, `difficulty`, `prereqs`, `prompt_seed`; текст параграфов в
задания не попадает, потому что задания генерируются по `prompt_seed`, а теорию
пишет `learning-material`. Двести страниц скана нужны были ради сорока строк
тематического плана.

## Цели

- завести курсы для 5–11 классов по десяти предметам ядра ОГЭ/ЕГЭ так, чтобы состав
  тем происходил из ФРП, а не из чужого учебника;
- сделать соответствие программе машинно проверяемым: у каждой темы есть страницы
  источника, и они лежат внутри загруженного куска программы;
- уложить импорт в существующий конвейер каталога, не заводя второго пути сборки
  карты тем;
- сделать прогон идемпотентным и делимым: повторный запуск продолжает с места
  остановки, отказ одного курса не отменяет остальные;
- снять безусловное назначение legacy-курсов, которое при шестидесяти курсах
  выдаёт пятикласснику математику 7 класса и не даёт снять курс вовсе.

## Не входит в задачу

- предметы, не ложащиеся на короткий проверяемый ответ (`number`, `text`,
  `choice`): литература, ИЗО, музыка, физкультура, технология;
- углублённые варианты программ — берётся базовый уровень, углублённый добавляется
  строкой манифеста;
- автоматический обход edsoo.ru за списком ссылок: манифест ведётся руками;
- отдельный справочник классов у `children`: класс остаётся отображаемой строкой
  курса, а назначение — родительским действием;
- ручной гейт оператора перед публикацией: публикация автоматическая, отбраковка
  машинная.

## Принятые решения

**Единица курса — предмет и класс.** «Математика, 7 класс» — один курс, собранный
из трёх учебных курсов ФРП (алгебра, геометрия, вероятность и статистика). Это
совпадает с устройством трёх нынешних курсов, с калибровкой предмета по триажу
(двенадцать экзаменационных тем) и с тем, как родитель думает о назначении.
Разделение на учебные курсы ФРП отвергнуто: курсов стало бы девяносто, родителю
пришлось бы назначать три вместо одного, а в курсе вроде «Вероятность и
статистика, 7 класс» тем меньше десятка — триаж на нём вырождается.

**Предметов десять:** русский язык, математика, английский язык, физика, химия,
биология, география, информатика, история, обществознание. С какого класса предмет
начинается, задаёт сама ФРП (физика с 7, химия с 8), поэтому число курсов —
следствие манифеста, а не отдельный список. Выходит около шестидесяти.

**Публикация автоматическая.** Прогон не останавливается на человеке; вместо гейта
работает машинная отбраковка, отсекающая курс и продолжающая прогон.

**Legacy-курсы получают новую редакцию, а не заменяются.** `math`, `russian` и
`english` объявляются курсами 7 класса, и ФРП-импорт для 7 класса кладёт в них
новую опубликованную редакцию. Назначения, история и идущие забеги целы: run
закреплён за старой редакцией, а новая активная тема включается автоматически.
Заведение новых id `math-7`/`russian-7`/`english-7` отвергнуто: оно потребовало бы
миграции назначений, а накопленный `topic_state` остался бы привязан к темам
архивного курса — ребёнок начал бы 7 класс с нуля.

## Устройство документа ФРП

Знание о вёрстке — основание всей нарезки, поэтому оно записано здесь.

Программа издана **на уровень образования**, а не на класс: 5–9 одним документом,
10–11 другим (у физики и химии — 7–9). Внутри документ делится на учебные курсы
заголовком `ФЕДЕРАЛЬНАЯ РАБОЧАЯ ПРОГРАММА УЧЕБНОГО КУРСА «…»`. Так, «Математика
5–9» содержит четыре: «Математика» (5–6), «Алгебра» (7–9), «Геометрия» (7–9),
«Вероятность и статистика» (7–9).

У каждого учебного курса есть разделы `СОДЕРЖАНИЕ ОБУЧЕНИЯ` и `ТЕМАТИЧЕСКОЕ
ПЛАНИРОВАНИЕ`, и оба разбиты подзаголовками `N КЛАСС`. Именно эти два раздела несут
состав тем; «Планируемые результаты» с личностными и метапредметными для карты тем
бесполезны и в срез не попадают. Два раздела одного класса **не смежны** — между
ними лежат предметные результаты.

Документы имеют текстовый слой (математика 5–9: 143 страницы, полмегабайта текста
`pdftotext`), поэтому OCR на сервере фактически пропустит страницы. В тематическом
планировании указаны часы — сигнал для `exam_weight`, который придётся нормировать:
схема `course-draft.json` допускает только `0..3`.

## Манифест источников

`content/frp/sources.json` — список программ, зафиксированный в репозитории, около
пятнадцати строк на десять предметов:

```json
{ "subject": "matematika", "title": "Математика", "level": "ooo",
  "url": "https://edsoo.ru/wp-content/uploads/2025/07/2025_ooo_frp_matematika-5-9_baza.pdf",
  "sha256": "…", "grades": [5, 6, 7, 8, 9], "courseId": { "7": "math" } }
```

Ведётся руками по двум причинам. Имена файлов нерегулярны: у математики
`2025_ooo_frp_matematika-5-9_baza.pdf`, у русского языка
`01_frp_russkij-yazyk_5-9-klassy_itog-na-sajt_1-2.pdf` — правила сборки URL не
существует, и выведенное правило ломалось бы молча. А `sha256` делает прогон
детерминированным и превращает выход новой редакции ФРП в явный отказ «файл на URL
изменился» вместо тихой подмены содержания.

Отображения «учебный курс ФРП → предмет» в манифесте нет: документ **и есть**
предмет. Всё, что найдено в документе математики для 7 класса, склеивается в
«Математика, 7 класс».

`courseId` называет идентификатор только там, где курс уже существует — 7 класс
математики, русского и английского. Остальные скрипт считает сам, детерминированно:
`frp-<subject>-<класс>`, то есть `frp-geografiya-5`. Идентификатор называет
`POST /api/admin/courses` полем `id`, а свой курс следующий прогон ищет только по
нему.

Спрашивать идентификатор у сервера и искать курс потом по паре «название + класс»
нельзя: display `title` и `grade` ключом не являются нигде, оператор вправе
переименовать курс в админке — и следующий прогон завёл бы **второй** «География,
5 класс», собрал и опубликовал бы его. У родителя два одинаковых курса, различить
нечем, прогресс детей остался бы на первом, а починить это нечем: розданные
идентификаторы вечны. Поэтому `subject` проверяется на форму при разборе манифеста
(`COURSE_ID_PATTERN` из `server/db.ts` и предел длины маршрута), а не на первом
отказе сервера.

## Нарезка

`scripts/frp-outline.ts` — чистая эвристика без ввода-вывода, по образцу
`scripts/toc.ts`. Вход — массив текстов страниц (`pdftotext` разделяет страницы
`\f`), выход — отрезки `{ учебныйКурс, класс, диапазоныСтраниц[] }`.

Правил три: заголовок учебного курса открывает учебный курс; `СОДЕРЖАНИЕ ОБУЧЕНИЯ`
и `ТЕМАТИЧЕСКОЕ ПЛАНИРОВАНИЕ` — единственные интересные разделы; `N КЛАСС` внутри
раздела задаёт класс. Границы слов пишутся как `(?!\p{L})`: `\b` в JS только ASCII
и на кириллице не срабатывает никогда.

Кусок «предмет + класс» собирается из нескольких диапазонов в один PDF одним
вызовом `qpdf --empty --pages src A-B src C-D -- out.pdf`. Для 7 класса математики
это шесть диапазонов от трёх учебных курсов; на выходе 15–25 страниц, то есть два
пакета `buildCourseDraft` вместо двенадцати по целому документу, и модель видит
только свой класс — темы 8 класса в 7-й не протекают.

`qpdf` и `pdftotext` — уже production-зависимости проекта, но нужны и на машине
запуска скрипта. Оба вызываются через `runChild`, не через `spawn`.

## Оркестрация прогона

`scripts/import-frp.ts` — HTTP-клиент админского API:

```sh
npm run import-frp -- --base-url https://edukator.ru --email <оператор> \
  [--subject matematika] [--grade 7] [--dry-run]
```

Клиентом, а не прямой записью в `control.db`, потому что каталог данных держит
замок сервера (`server/index.ts:268`): скрипт, взявший тот же замок, не может
работать при живом сервере — так устроены `prefetch` и `adopt`. Заодно это
снимает вопрос, где брать OCR: его делает сервер на Ubuntu, а скрипт запускается
откуда угодно.

Пароль оператора читается со stdin общим `createSecretReader`, а не флагом:
аргументы видны в `ps` и остаются в истории оболочки. Разбор аргументов идёт общим
`scripts/account-args.ts`, но `--data-dir` этот скрипт не принимает: каталога
данных у него нет вовсе, он ходит по HTTP.

`--dry-run` проходит всё до первой записи на сервере: скачивает, сверяет `sha256`,
режет и печатает, какие куски и в какие курсы поедут, — и не создаёт ни курса, ни
черновика, ни источника. Скачанные документы кладутся в `--cache-dir` (по умолчанию
временный каталог прогона) и переиспользуются между запусками по `sha256`: качать
одну программу заново для каждого из пяти её классов незачем.

Изменяющие запросы сверяют источник целиком, поэтому клиент обязан слать
`Origin: <base-url>` руками — браузерных заголовков у него нет, и без этого каждый
`POST` вернёт 403.

Шаги на курс: скачать документ и сверить `sha256` → нарезать кусок → взять курс из
манифеста или создать → открыть черновик → загрузить кусок → дождаться `ready`
источника → запустить сборку и дождаться её → проверить черновик → опубликовать.

Курсы идут строго по одному. Параллелить нечего: OCR-очередь на сервере
однопоточная, а `catalogCodexConcurrency` равен единице — второй поток встал бы в
ту же очередь.

Отказ одного курса прогон не отменяет: курс уезжает в `failed[]` и доносится кодом
возврата, как у `backupDataDir` и `prefetchChildren`. Черновик остаётся
неопубликованным и виден в админке.

Идемпотентность даётся почти даром: загрузка источника сама отвечает `duplicate`,
повторный запуск подхватывает курс со стадии остановки, а курс с уже
опубликованной редакцией от того же `sha256` пропускается целиком. Это же делает
осмысленными `--subject` и `--grade`.

В журнал аварий скрипт не пишет ничего. `LOG_EVENTS` — закрытое объединение, и у
каждого имени обязано быть место вызова; `backup-failed` и `prefetch-failed` там
потому, что их зовёт cron и кода возврата не видит никто. Импорт запускают руками,
каталога данных у него нет — хватает stderr и кода возврата.

Цена для сервера: `buildCourseDraft` занимает **оба** бюджета — свой админский и
один из двух слотов общего `codexConcurrency`, которым греется банк заданий детям.
Пока идёт прогон, прогрев идёт вполовину медленнее. Суточные квоты детей импорт не
тратит: они считаются на ребёнка, а каталог к ним не относится. Прогон на
шестьдесят курсов запускается ночью.

## Машинная отбраковка

Публикация без человека требует, чтобы непубликуемое отсекалось правилом. Скрипт
читает собранный черновик и прогоняет пять проверок до `publish`.

**Граф.** `buildTopicGraph` на темах черновика — тот самый код, что уже ловит циклы
в `prereqs`, ссылки на несуществующие темы и предпосылку с недостаточным
`exam_weight`. Гнать его надо **до** публикации: опубликованная битая редакция
иначе сломается у ребёнка, при чтении провайдером.

**Размер.** Меньше `MIN_IMPORT_TOPICS = 8` тем — почти всегда промах нарезки: модель
получила не тот кусок. Верхняя граница в 60 стоит в схеме сама.

**Ссылки внутри своего куска.** Схема требует у темы хотя бы один `source_ref`, но
не проверяет, что `page_from`/`page_to` попадают в загруженный источник. Ссылка за
его границу означает выдуманные номера.

**Покрытие куска.** Доля страниц источника, на которые ссылается хоть одна тема,
не ниже `MIN_IMPORT_COVERAGE = 0.6`. Низкая доля означает, что модель прочитала первые
страницы и досочинила остальное, — ровно тот отказ, который иначе заметил бы только
ребёнок на занятии.

**Сохранность прогресса** — только для `math`, `russian`, `english`. Новая редакция
вправе переименовать темы, но если она сохранила `existing_id` у трёх тем из
двадцати трёх, накопленный `topic_state` детей обесценится. Доля сохранённых
идентификаторов ниже `MIN_KEPT_TOPIC_IDS = 0.5` отправляет курс в `failed[]`, а число
печатается в отчёт по курсу.

Отбраковка — не гейт для человека: она отсеивает курс и идёт дальше.

## Legacy-курсы и назначения

`bootstrapLegacyCourses` разделяется надвое, и назначающая половина исчезает.

Заведение остаётся: на чистом каталоге данных три курса по-прежнему создаются из
`content/curriculum/*.json`. Это идемпотентно, курс с существующим идентификатором
пропускается, и ФРП-импорту не мешает — импорт кладёт в `math` новую редакцию, а
следующий старт видит курс на месте и не делает ничего.

Безусловное назначение уходит целиком. Сейчас каждый старт вписывает все три курса
каждому ребёнку и переигрывает это после снятия — то есть снять курс с ребёнка
невозможно в принципе. При шестидесяти курсах правило вредно: колонки класса у
`children` нет, угадать за родителя нечем, а пятикласснику назначалась бы
математика 7 класса. Назначение — родительское действие, `assignCourseWithExclusions`
и `unassignCourse` уже есть.

Существующие назначения не трогаются: строки `child_courses` остаются, дети
занимаются тем же, история и `topic_state` целы. Меняется одно: новый ребёнок
заводится без курсов, и родитель выбирает их сам.

Цена — в харнессах. `tests/server-harness.ts` и `e2e/harness.ts` зовут
`bootstrapLegacyCourses` ради побочного эффекта назначения ребёнку, заведённому
после старта, и это записано в их комментариях. Оба получают явный помощник
назначения. Правка механическая, но широкая, и проводится **отдельной задачей плана
до** импорта: тогда красный тест указывает на одну причину, а не на две сразу.

## Тестирование

`scripts/frp-outline.ts` — юниты на синтетическом тексте страниц, без единого PDF.
Успешные пути и ошибочные: класс без тематического планирования, два учебных курса
подряд, отсутствующий заголовок класса, кириллическая граница слова.

`scripts/import-frp.ts` — против поддельного HTTP-сервера: порядок шагов,
идемпотентность обоих видов, отказ одного курса не отменяет прогон, код возврата
называет `failed[]`. Скачивание — за подменяемым интерфейсом, как `CodexRunner` и
`OcrRunner`: на edsoo.ru в тестах не ходит никто.

`qpdf` и `pdftotext` — исполняемой заглушкой, shell-скриптом в temp-каталоге, а не
моком `spawn`: только так проверяются коды возврата.

Каждая из пяти проверок отбраковки — свой тест, красящий курс по одной причине.
`MIN_IMPORT_TOPICS = 8`, `MIN_IMPORT_COVERAGE = 0.6` и `MIN_KEPT_TOPIC_IDS = 0.5` —
калибровочные константы с тестом на буквальное значение: тест, строящий ожидание из той же
константы, её подмену не поймает.

Новые файлы добавляются в `vitest.config.ts` под пофайловый порог 80%. Нового e2e
сценария не требуется — configurable-course уже покрывает publish и назначение, — но
правка харнессов делает `npm run test:e2e` обязательным.

## Критерии приёмки

- `npm run import-frp` заводит и публикует курсы 5–11 классов по десяти предметам
  манифеста; число курсов следует из того, с какого класса ФРП вводит предмет.
- У каждой опубликованной темы есть хотя бы одна ссылка на страницы, и все ссылки
  лежат внутри загруженного куска программы своего курса.
- Повторный запуск на завершённом каталоге не создаёт ни одного нового курса,
  черновика или источника и завершается нулевым кодом.
- Прерванный прогон продолжается с места остановки; курс, не прошедший отбраковку,
  остаётся неопубликованным черновиком, попадает в `failed[]` и не мешает
  остальным; код возврата ненулевой.
- Курсы `math`, `russian` и `english` получают новую опубликованную редакцию;
  назначения детей, `topic_state` и незакрытые забеги переживают её, а забег,
  начатый до публикации, доигрывается на прежней редакции.
- Ни один старт сервера больше не назначает курс ребёнку; снятый родителем курс
  остаётся снятым после перезапуска.
- Новый ребёнок заводится без назначенных курсов.
- Чисты `npm test`, `npm run coverage`, `npm run typecheck`, `npm run lint`,
  `npm run build:web` и `npm run test:e2e`.
