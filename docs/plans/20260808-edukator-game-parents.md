# Edukator: игровой слой и родительский дашборд (этап 4 из 5)

## Overview

Четвёртый этап добавляет мотивационный и обзорный слой поверх уже работающих
забегов:

- стрик по календарным дням с завершённым обычным забегом;
- карту тем и боссов: пять свежих заданий подряд без подсказок, только 5 из 5;
- окончательное закрытие темы после победы;
- прозрачный read-only дашборд `/parents` со скользящим окном в семь суток;
- прогнозы, честное активное время, проблемные темы, ленту и флаги для родителей.

В этап **не входят** диктант, ElevenLabs/TTS и пробный экзамен. Они образуют
отдельный этап 5. Авторизация, отдельный родительский режим и ссылка на
`/parents` в интерфейсе также не добавляются: родители знают прямой адрес,
ученик может открыть ровно ту же страницу.

Основная спека:
[`docs/superpowers/specs/2026-08-07-edukator-design.md`](../superpowers/specs/2026-08-07-edukator-design.md).
Реализованный этап 3:
[`docs/plans/completed/20260808-edukator-run-triage.md`](completed/20260808-edukator-run-triage.md).

## Approved Decisions

- Стрик продлевает только завершённый обычный `run`; триаж и босс не считаются.
- Граница дня — локальная дата `Europe/Moscow`. Незавершённый сегодняшний день
  не обрывает вчерашнюю серию.
- Босс доступен при `mastery > 0.75`, а не при равенстве порогу.
- Бой состоит ровно из пяти заданий без подсказок. Победа — только 5 из 5.
- Любая подтверждённая ошибка завершает бой поражением без отдельного штрафа,
  списания XP или искусственного снижения `mastery`.
- После поражения календарного кулдауна нет. Новый бой доступен, когда готов
  новый провалидированный батч из пяти заданий, которых ученик ещё не видел.
- Если ответ оспорен, бой приостанавливается. Подтверждённый спор продолжает
  тот же бой; отклонённый спор завершает его поражением.
- Победа закрывает тему навсегда: она больше не попадает в обычный план и
  тёплую очередь. Это осознанное продуктовое решение без интервального возврата.
- Задания босса не забираются из обычной очереди. Они генерируются отдельно,
  проходят существующую независимую валидацию и резервируются полным набором.
- Общая запись заданий не дублируется: `bank.ts` получает внутренний примитив,
  которым пользуются обычный банк и атомарный резерв босса.
- `/parents` использует скользящие семь суток. План — фиксированные 630 минут,
  факт — сумма `attempts.duration_ms`, а не время между стартом и финишем забега.
- Числовой прогноз на `/parents` не скрывается при широкой полосе, но явно
  помечается как предварительный.
- Флаг снижения нагрузки появляется, только если нижняя граница прогноза
  достигла 4.0; одного центрального значения 4.1 недостаточно.

## Context (from discovery)

- Текущая версия схемы — 9; `runs.kind` допускает только `run | triage`.
- `topic_state` хранит учебное состояние, но не имеет постоянного признака
  закрытия темы.
- `task_bank.status` допускает `pending | valid | rejected | used`, а
  `takeTask` атомарно забирает только `valid`.
- `storeTasks` уже является единственной реализацией отпечатка, дедупликации,
  сериализации структурированного задания и вставки батча.
- `TaskProducer` воркера возвращает уже сгенерированные и провалидированные
  задания и использует общий `CodexConcurrency`.
- Обычное занятие пишет `attempts.run_id`, начисляет XP и разбирает спор через
  `server/session.ts`; босс должен переиспользовать этот путь записи.
- `finishRun` пишет снимки прогноза. Истории достаточно для семидневного тренда,
  но выбор точки сравнения для дашборда нужен отдельный.
- Главный экран уже получает план, прогноз и триаж одним запросом. Новые данные
  можно добавить в его read model без дополнительных клиентских waterfall.
- Клиент сейчас выбирает экран по query string. Для прямого `/parents` роутер
  должен учитывать `window.location.pathname`, сохранив SPA fallback Fastify.
- Все семь существующих таблиц перечислены в `TABLES` и проверяются
  `validateSchema`; новые таблицы и индексы должны войти в эту проверку.

## Development Approach

- Доменные правила босса, стрика и дашборда проверяются unit-тестами без HTTP и
  React. Маршруты остаются адаптерами.
- Миграции выполняются последовательно и транзакционно. Перестройка таблиц с
  изменёнными `CHECK` сохраняет идентификаторы и завершается `foreign_key_check`.
- Вызовы Codex никогда не идут внутри транзакции. Транзакция охватывает только
  claim подготовки и атомарную запись готового набора.
- Резерв босса не смешивается со статусом обычной очереди и не уменьшает её
  целевой остаток.
- Все временные решения принимают `now`/часовой пояс через параметры, чтобы
  тесты не зависели от часов машины.
- Каждая задача приносит успешные и ошибочные тесты; полный набор проходит до
  перехода к следующей задаче.
- План обновляется сразу при обнаружении новых обязательных работ; выполненные
  пункты помечаются `[x]` по одному, а не пачкой в конце.

## Testing Strategy

- **Unit**: `boss.ts`, подготовка батчей, `streak.ts`, `parents.ts`, исключение
  закрытых тем планировщиком.
- **Database**: миграция с версии 9, ограничения новых статусов, уникальность
  живого батча и пяти позиций, целостность внешних ключей.
- **Routes**: boss/home/parents contracts, 4xx для состояния и 503 при
  недоступной базе; наружу не уходят ответы и внутренние topic id дашборда.
- **Components**: карта тем, состояния подготовки, бой, пауза спора, победа,
  поражение и все блоки `/parents`.
- **E2E**: победа над боссом закрывает тему; `/parents` показывает подготовленные
  показатели. Настоящий Codex не вызывается.
- **Гейты**: `npm test`, `npm run coverage`, `npm run typecheck`, `npm run lint`,
  `npm run build:web`, `npm run test:e2e`.

## What Goes Where

- `server/boss.ts` — eligibility, жизненный цикл боя и атомарное закрытие темы.
- `server/boss-prep.ts` — claim, генерация и резерв свежего полного батча.
- `server/streak.ts` — чистый расчёт текущей и лучшей серии.
- `server/parents.ts` — единая read model дашборда и правила флагов.
- `server/routes/boss.ts`, `server/routes/parents.ts` — HTTP-границы.
- `web/src/BossScreen.tsx`, `web/src/ParentsScreen.tsx` — новые экраны.
- `web/src/boss-api.ts`, `web/src/parents-api.ts` — клиентские контракты.
- `tests/*.test.ts`, `web/src/*.test.tsx`, `e2e/edukator.spec.ts` — проверки
  соответствующих слоёв.

## Technical Details

- `BOSS_MASTERY = 0.75`; eligibility использует строгое `>`.
- `BOSS_TARGET = 5`; победа требует `correct === total === 5`.
- `PARENTS_WINDOW_DAYS = 7`; `PLANNED_MINUTES = 630`.
- Порог бездействия — три **полных** московских календарных дня.
- Плато прогноза — пять суток при наличии занятий и минимум двух сравнимых
  снимков; отсутствие данных не называется плато.
- Активное время агрегируется в миллисекундах и округляется только в HTTP/read
  model. Дневные значения и общий итог получаются из одной выборки.
- В boss reserve попадают только задания, прошедшие тот же `parseTaskBatch`,
  независимый validator и `questionFingerprint`, что обычный банк.
- `boss_tasks` фиксирует порядок; порядок по `task_bank.id` или `created_at` не
  используется как скрытая бизнес-логика.
- Нельзя держать вызов `TaskProducer` внутри SQLite-транзакции.
- Конкурентные start/finish/dispute переходы используют immediate-транзакции и
  проверяют текущее состояние заново под записью.
- Часовой пояс — именованный `Europe/Moscow`, не текущая зона ОС. Если рантайм
  не предоставляет корректный IANA timezone, сервер должен упасть при старте с
  ошибкой настройки, а не молча считать UTC-дни.

## Post-Completion

Автотесты не закрывают следующие продуктовые проверки:

1. Дать ученику пройти босса и проверить, воспринимается ли 5 из 5 как честный
   вызов, а поражение — как предложение попробовать ещё, а не наказание.
2. Показать `/parents` ученику и родителям одновременно: термины и цифры должны
   одинаково пониматься обеими сторонами и не звучать как скрытая слежка.
3. Сверить «честное время» с одним реальным учебным днём: сумма активных ответов
   должна субъективно соответствовать работе, даже если она меньше времени с
   открытой вкладкой.
4. Вычитать флаги живым человеком: это наблюдения для разговора, не команды
   усилить контроль или наказать за пропуск.
5. После недели использования решить отдельно, нужен ли этапу 5 пробный экзамен
   до диктанта; это не расширяет текущий план автоматически.
