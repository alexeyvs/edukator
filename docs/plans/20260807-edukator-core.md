# Edukator: ядро и данные (этап 1 из 4)

## Overview

Первый из четырёх этапов реализации Edukator — приложения для подготовки
13-летнего ученика к вступительным тестам в 7 класс по русскому, английскому и
математике за 40 часов.

Этот этап строит **всё, что не требует ни LLM, ни интерфейса**: каркас проекта,
базу данных, карту тем из учебников и четыре модуля чистой логики — нормализатор
ответов, модель знаний, планировщик и расчёт прогноза оценки.

Ценность именно такого разреза в том, что ядро полностью детерминированно и
покрывается тестами без единого обращения к внешним сервисам. Ошибка в формуле
`mastery` или в приоритизации тем — самый дорогой класс дефектов в этом проекте:
она тихо портит весь учебный план, не падая ни одним тестом, если тестов нет.
Поэтому ядро отделено и закрывается первым.

Утверждённая спека: `docs/superpowers/specs/2026-08-07-edukator-design.md`.

**Этапы 2-4 (не входят в этот план):** генерация заданий через codex CLI; экран
забега и триаж; отображение уже реализованного прогноза, дашборд, боссы и диктант.

## Development Approach

- **Testing approach**: TDD — тест пишется до реализации для всех четырёх модулей
  ядра (`normalize`, `mastery`, `scheduler`, `forecast`). Для каркаса, схемы БД и
  скриптов извлечения допустим обычный порядок.
- Каждая задача доводится до конца перед переходом к следующей.
- Изменения мелкие и сфокусированные.
- **КРИТИЧНО: каждая задача обязана содержать новые или обновлённые тесты**
  для кода, изменённого в этой задаче.
  - тесты не опциональны — это обязательная часть чеклиста
  - юнит-тесты на новые функции и методы
  - юнит-тесты на изменённые функции и методы
  - новые тест-кейсы на новые ветви кода
  - обновление существующих тестов при изменении поведения
  - тесты покрывают и успешные, и ошибочные сценарии
- **КРИТИЧНО: все тесты обязаны проходить до начала следующей задачи** — без исключений.
- **КРИТИЧНО: этот файл плана обновляется при изменении объёма работ по ходу.**
- Тесты запускаются после каждого изменения.
- Обратная совместимость поддерживается.

## Testing Strategy

- **Unit tests**: обязательны для каждой задачи (см. Development Approach).
- **E2E tests**: интерфейса на этом этапе нет, e2e не применяются. Они появятся
  на этапе 3 вместе с экраном забега.
- **Тесты-инварианты карты тем** (задача 3) отдельно важны: они проверяют
  структуру (уникальность `id`, диапазоны, существование `prereqs`, отсутствие
  циклов), но **не содержательную корректность** тем. Содержание проверяет
  человек — вынесено в Post-Completion.

- Новые обнаруженные задачи добавляются с префиксом ➕.

⚠️ **Все три учебника — сканы без текстового слоя:** `pdf-parse` вытаскивает из
818 страниц ноль символов. Плана «извлечь текст пакетом и не тянуть системные
зависимости» оказалось недостаточно, поэтому добавлен откат в OCR:
`scripts/ocr-pdf.swift` рендерит страницу через PDFKit и распознаёт системным
Vision (`ru-RU` + `en-US`). Vision выбран вместо tesseract/ocrmypdf потому, что
он уже есть в macOS, знает русский и не требует ни установки, ни загрузки
языковых моделей; плата — эта ветка работает только на macOS, о чём скрипт
сообщает внятной ошибкой. `pdf-parse` остался первой попыткой: для PDF с
текстовым слоем OCR не запускается.

➕ Ручной `--pages` отключает поиск страниц, но не проверку качества текстового
слоя: один штамп или номер страницы в диапазоне скана больше не блокирует OCR.
Качество проверяется для каждой страницы отдельно, поэтому богатый текстовый
слой соседней страницы не скрывает скан оглавления в гибридном PDF.
Явное сочетание `--pages ... --no-ocr` остаётся способом довериться короткому
текстовому слою намеренно.

➕ Обнаружено по ходу: OCR читает оглавление по колонкам — сначала все названия,
потом отдельным блоком все номера страниц, а «§» часто распознаётся как «$».
Эвристика «название … номер страницы» на таком тексте не работает, поэтому
пункт оглавления опознаётся тремя способами: отточие с номером в конце строки,
маркер раздела в начале (`§`, `$`, «Глава», «Урок», `Unit`, …) и голый номер
страницы. Голые номера засчитываются только на странице, где уже есть хотя бы
три названия, — иначе страница «Ответы к упражнениям» выглядит как идеальное
оглавление. Дополнительно требуется, чтобы в названии было не меньше трёх букв:
это отсекает нумерацию задач вида «1.1. 42».

➕ Оглавление в русских учебниках бывает и в конце книги (математика — с. 333,
русский — с. 314-318, английский — с. 3), а OCR каждой страницы стоит примерно
секунду. Поэтому просматриваются не все страницы, а по 15 с каждого края
(`--scan`), и подряд идущие страницы-кандидаты склеиваются в один кусок.

⚠️ `\b` в JS считает словом только ASCII, поэтому `/^глава\b/` не находит
границу после кириллицы и не срабатывает никогда. Граница слова выражена через
`(?!\p{L})`.
