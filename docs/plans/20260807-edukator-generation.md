# Edukator: генерация заданий через codex (этап 2 из 4)

## Overview

Второй этап реализации Edukator. Ядро из этапа 1 умеет выбирать тему и оценивать
ответ, но заданий у него пока нет. Этот этап их производит.

Строятся пять вещей: клиент codex, генератор батчей, валидатор, воркер тёплой
очереди и посевной банк. Задача этапа сформулирована жёстко: **ученик никогда не
видит спиннер и никогда не получает кривое задание**. Первое обеспечивает
опережающая генерация, второе — независимая перепроверка каждого задания.

Замеры этапа подготовки: батч из 5 заданий с подсказкой, разбором и шуткой —
23.6 секунды на `gpt-5.6-terra`. Один батч покрывает 5-10 минут решения, поэтому
воркер успевает пополнять очередь, пока ученик занимается.

Утверждённая спека: `docs/superpowers/specs/2026-08-07-edukator-design.md`.
Предыдущий этап: `docs/plans/20260807-edukator-core.md` (реализация завершена,
открыты только ручные release gates в его Post-Completion).

**Этапы 3-4 (не входят в этот план):** экран забега и триаж; отображение
прогноза, родительский дашборд, боссы тем, диктант.

## Development Approach

- **Testing approach**: TDD для чистой логики (сборка промпта, разбор ответа,
  сверка валидатора, политика очереди). Для процессов и I/O допустим обычный
  порядок с подстановкой процесса-заглушки, как это уже сделано в
  `tests/build-curriculum.test.ts`.
- **Ни один тест не вызывает настоящий codex.** Реальные вызовы идут только в
  задаче наполнения посевного банка, вручную, и их результат коммитится.
- Каждая задача доводится до конца перед переходом к следующей.
- **КРИТИЧНО: каждая задача обязана содержать новые или обновлённые тесты**
  для кода, изменённого в этой задаче.
  - тесты не опциональны — это обязательная часть чеклиста
  - юнит-тесты на новые и на изменённые функции
  - новые тест-кейсы на новые ветви кода
  - тесты покрывают и успешные, и ошибочные сценарии
- **КРИТИЧНО: все тесты обязаны проходить до начала следующей задачи.**
- **КРИТИЧНО: этот файл плана обновляется при изменении объёма работ по ходу.**

## Testing Strategy

- **Unit tests**: обязательны для каждой задачи.
- **E2E tests**: интерфейса на этом этапе нет; появятся на этапе 3.
- **Тесты воркера** проверяют политику (пороги пополнения, предел
  одновременных процессов, откат на посевной банк) на подставном генераторе,
  без запуска процессов.
- **Содержательное качество заданий** автотестами не проверяется — его
  проверяет человек по выборке из посевного банка (Post-Completion).

## Progress Tracking

- Выполненные пункты помечаются `[x]` сразу по завершении.
- Новые обнаруженные задачи добавляются с префиксом ➕.
- Проблемы и блокеры документируются с префиксом ⚠️.
- План держится в синхроне с фактически сделанной работой.

## What Goes Where

- **Implementation Steps** (`[ ]`): всё, что достижимо внутри репозитория.
- **Post-Completion** (без чекбоксов): выборочная вычитка сгенерированных
  заданий человеком, заполнение профиля ученика.

      руками `id`, а второй ответ сдвинул бы `mastery` дважды за одно задание.
      Проверка, запись попытки и сдвиг модели идут одной `immediate`-транзакцией
- ➕ подтверждённый спор пересчитывает модель новым `recomputeTopicState`

- ➕ заведённый спор ищется раньше проверки «попытка и так засчитана»: после

- ➕ `buildServer` держит одно соединение с базой (транзакции занятия нельзя

- ⚠️ забеги (`runs`) этими маршрутами не заводятся, `attempts.run_id` остаётся
      пустым: их жизненный цикл — экран забега этапа 3. На планировщик это влияет
      только тем, что `topicsUsedToday` пуст, то есть тема держится, пока её

## Technical Details

**Поток генерации:**

```
планировщик → активные темы → воркер → генератор (codex, батч 5)
                                     → валидатор (codex, без ответов)
                                     → сверка через normalize.ts
                                     → task_bank
```

**Формат задания в `task_bank`:** `topic_id`, `question`, `answer`,
`accept` (JSON), `hint`, `explain`, `joke`, `difficulty`, статус, отпечаток
формулировки.

**Вызов codex:** `--ephemeral --skip-git-repo-check --output-schema
schemas/tasks.json -o <файл>`, stdin закрыт, модель `gpt-5.6-terra`.

**Пороги воркера:** пополнять ниже 4 заданий на активную тему, останавливаться
на 8, не более двух одновременных вызовов codex.
